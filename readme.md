# Trim 使用说明

> Trim 是一款 Windows 11 清理与优化小工具，中文界面，原生 Fluent Design 风格。
> 由小旭个人开发，仅供个人测试交流使用，使用风险请自行承担。

> 版本 **0.5.5**（2026-10-03 十四项目对标 · R1 + M2/M3/M4 + C1 + E 系列批次）：本版把「优化项能不能被检出、能不能被还原、依据是什么」这三件事从**没有答案**变成**有机械判据**。① **检测盲区修复 13 项**（§M2）—— 原先 31 项优化项体检恒显示「未生效」，用户点「立即执行」会**重复施加同一批系统改动**（与 v2-M1 的重复项 bug 同一种形态：把「没检到」显示成「没有」）。分三类落地：**B 类 6 项**（服务启动类型，走 R0-b 已建的 `service_start_type_is`，零新原语，100 个断言）·**A 类 6 项**（注册表值回读，新增 `read_reg_binary_opt` 读 REG_BINARY —— `MitigationOptions` / `Scancode Map` 这类多字节值此前完全检不出）·**2 个 dynamic 项**（`svc_mem_gb` / `perf_wu_pause`，新增「值 ∈ 合法集合」与「现在 ∈ 区间」两种判据形态 + `read_reg_qword_opt` 读 FILETIME）。② **修一个结构性 bug**（比上面 13 项更重要）：`collect_checks` 开头 `let Some(steps) = steps else { return checks }` 会让**数据层没有 `steps` 的项**（dynamic 项）永远走不到侧表分支 —— 症状与 v0.5.0 的缺陷一模一样，排查时极容易误判成「侧表没登记」。③ **还原后回读验证**（§M3）—— 值级还原此前只信 `RegSetValueExW` 的返回值（那是「API 调用成功」不是「值写对了」），现在写完逐条独立回读、按类型比对，不一致时**保留备份**并如实报错（fail-closed，清掉记录就等于删掉用户唯一的还原依据）。④ **优化目录纳入 ed25519 签名**（§M4）—— 126 个「会改用户系统」的优化项此前**零校验**；现在装载前验签，失败返回空目录并写 error 日志（不放行也不 panic —— panic 会把磁盘清理等无关域一起带崩）。数组顶层签名踩了两个坑：Node 的 `Object.entries(array)` 会把 `[{…}]` 变成 `{"0":{…}}` 导致两侧字节不同，以及 `arr._sig = …` 静默无效（`JSON.stringify` 不序列化数组的非索引属性）。⑤ **新增三张侧表 + 四条门禁**（`optimizer-writes.json` 写入坐标 / `optimizer-provenance.json` 高危项可解释溯源 / `optimizer-defaults.json` 出厂默认值 / `optimizer-groups.json` 分类两层结构），门禁从 36 条扩到 **39 条**（必跑 37 + 可选 1 + 退役 1），新增 `check-optimizer-write-contract`（9 组断言 + 19 条正向自检）、`check-optimizer-groups-sidecar`（5 组 + 6 条自检）、`check-elapsed-facts`（3 组 + 14 条自检）。⑥ **界面补强**（§E）—— 优化页顶部 5 分类加权**态势分**（零依赖 SVG 环，权重显式声明；**空分类返回 100 而非 0** ——「没东西要做」是满分不是零分）· 优化项行内**收藏星标**（LRU 上限 10 的最近使用）· 已优化项的**逐项还原入口**（无备份时置灰 + `data-tip` 说明原因，而不是给一个点了必然失败的按钮）。⑦ **批量预检**（§M1）—— 批量执行前先整批评判（权限 / 高危确认 / 本机可执行性），被拦项先告知再执行，不再「第 5 项失败时前 4 项已落盘」。⑧ **junction 跳过留痕**（§R1-2）—— 清理/扫描遇到联接点（junction/挂载点）会跳过（防重复计数与成环），此前**静默跳过**，用户看不出「为什么少了这些文件」；现在计数并透出到界面。⑨ **区域耗时统计**（§E4）—— 内存清理 / 右键菜单 / 启动项三域的每条结果带耗时，**只加字段不参与任何判定**。⑩ **「优化项与规则库不热更」写成有意设计**（readme 承诺 + 门禁钉住）—— 规则库随版本交付并签名，没有「检查更新并热替换」入口；残留规则库的「在线更新」是**用户点击触发**的显式替换，不是后台定时替换。⑪ **两处方案修正**（都写进了门禁注释）：**C3 硬件条件门控废弃** —— 机械重算 126 项后确认 0 项的「硬件差异」是生效前提（NVIDIA 键路径是**写入目标**不是前置条件），建门控表恒为空，纯维护成本；**C1 只登记可机械复核的 10 项** —— Windows 出厂默认值无权威来源、实测原值因机而异，写进去就是编造依据，而这一项的价值恰恰在「依据可判定」，所以其余 116 项显式标 `unknown` 而不猜值。⑫ 顺手修了 6 处判红实验暴露的**判据自身缺陷**（三次是同一类坑：含 substring 的判据在同类代码多处时会假红或漏红，判据必须绑到「足够宽的结构特征」上），以及只读档来源校验的**独立真源门禁**（D5 组：只读档却无子窗消费方 = 白给放宽，此前 `check-guard-types` 的 A/B/C 三组全都不管这一档）。
> **未验证**（如实标注）：① **优化页新 UI 未起前台窗口目检** —— 态势分环的尺寸/对齐、收藏星标与还原按钮在 12 列窄看板下会不会挤掉项名，静态门禁（对比度 / token / HTML 合同）查不出布局问题。② **两处 `#[ignore]` 的真机断言未跑** —— `regAbsent` 删除语义方向（需真改 HKLM 更新策略键）与 `regTimeWindow` 区间判据（需真机写入暂停区间），按「快速组零副作用」纪律归入发布前门禁组。③ **13 项检测的期望值全部来自静态推导**，未在真机上逐项确认过实际读回形态。④ **72 条「只读档却只有主窗在用」的登记待逐条评审改档** —— 本版只做棘轮（让新增白给放宽变红），没有改既有档位（改档会锁死功能，AGENTS §3 的M1~M3 教训）。⑤ **M4 的签发侧设计有四条未兑现**：按域拆分私钥（现为一把钥匙开三个锁，单域泄露波及三域）、公钥清单 + `kid`、`notAfter` 过期检查、轮换演练（详见 `docs/规则库签发侧设计-2026-10-03.md` 第五节「不要误以为已实现」）。

## 二、磁盘清理

**操作步骤：**

1. 进入页面后点 **扫描大小**，等待扫描完成；大小显示为 **—** 的条目表示当前权限无法统计（系统目录需管理员权限、注册表项本身没有字节概念），不代表里面没有可清理内容，也不等于 0 字节；
2. Windows 系统类是二级目录（更新与组件残留 / 日志与诊断 / 缓存与预读 / 临时文件 / 崩溃转储 / 隐私历史 / 过时备份），展开后可单独勾选；
3. 勾好要清理的项目，点 **开始清理**。执行策略为固定默认（v3.3.0 起不再提供勾选项）：清理后自动重建被删除的空目录（避免依赖这些目录的软件报错）；常规清理 v3.3.0 起固定为永久删除、不进回收站（QQ/微信接收文件走回收站）；注册表项与 DISM 清理直接执行（注册表删除前自动 .reg 备份）；**不执行强制删除**，被占用文件不重试、记为残留；
4. 每个条目行尾的 **明细** 按钮可以先看看会删哪些文件（只读预览，最多列 600 条，可复制完整清单）；清理后如果有文件被占用没删掉，会提示「N 项仍有残留」，关掉相关软件或重启后再试即可；**释放空间按删除前后的实际差值统计**，只删掉一部分的条目不会按账面大小冒领，会计入「清理失败」提示并在应用日志里标为部分成功；
5. **风险等级**：低风险项放心清；高风险项共 2 个——**Windows Installer 补丁缓存**和 **DISM 组件清理**，按默认策略不会执行，执行结果中会如实标注「按默认策略跳过」。
6. **v3.7.2 修复**：部分机器的用户临时目录是 8.3 短路径形式（如 `C:\Users\ADMINI~1\...`），此前清理「临时文件」会被受保护路径安全闸误判为受保护而失败；现安全闸会先把真实存在的短路径展开为长路径再判定，误杀消除，对不存在路径的 fail-closed 拒绝语义保持不变。
7. **v3.7.3 修复**：清理前「部分文件正在被使用」弹窗的两处进程结束隐患——① 占用者名单里出现的 **Trim 自己**（Windows 会把发起检测的应用也计入占用者）不再提供「结束进程」入口，此前点击「立即结束进程」会导致软件自身退出、清理中断；② **Windows 资源管理器** 被占用时同样只提示、不再提供结束入口（结束资源管理器会导致任务栏和桌面消失）。这两类被占用的文件仍会在结果中如实报告为残留，关闭相关程序后可再清理。

**覆盖范围：** Windows 缓存和临时文件、显卡缓存（NVIDIA / AMD / Intel）、浏览器缓存（Chrome / Edge / Firefox / QQ浏览器，自动覆盖全部用户 Profile）、常用软件缓存（Steam、Epic、Office、VS Code、JetBrains、npm/pip/NuGet、网易云音乐、微信、QQ、抖音）、注册表隐私痕迹（最近文档、运行记录、名称缓存），以及 QQ、微信接收文件目录。

**规则库（清理清单）更新：**

- 点工具栏 **更新规则库** 即可在线检查更新，程序会自动依次尝试多个下载源；下载内容会做完整性校验，损坏或被篡改的更新包会被直接拒绝，更新后立即生效，无需重启软件；
- 没装的软件对应条目扫描时会自动隐藏（比如没装 Firefox 就不显示它）；
- 如果某条目要求先关闭相关程序（如 Chrome、资源管理器），扫描结果的路径列会出现琥珀色「需关闭: xxx」标签；**执行时程序还开着的话，整条自动跳过并写明原因**，不会清一半留一半；
- 想开关内置清理规则：把 `{id, enabled}` 结构的 JSON 文件放进 `%APPDATA%\Trim\cleanup\custom\`，仅支持开关内置条目（多字段文件会被拒载，新 id 不会追加）（**这个目录刻意与旧版共用、不随应用数据目录改名**，这样你在旧版里攒的自定义规则升级后直接可用）；
- 默认下载源取不到时（例如私有仓库返回 404），可在 `%APPDATA%\Trim\cleanup\update-source.json` 里配置自己的下载地址和请求头；程序位于 git 仓库内时也会尝试直接用本机 git 拉取。

**图片预览：** 文件目录类条目右侧的 **预览 (N)** 按钮会打开独立的图片预览窗口，支持左右方向键切换、缩放（−/+）、1:1 还原、旋转，窗口内可以直接删除当前图片；删掉后主窗口的文件列表和容量统计会实时同步，同步链路上任一环节失败（预览窗发不出通知、主窗口不存在、主窗刷新出错）都会明确提示（不会静默假装已同步）。

## 三、内存清理与应用进程管理

**内存清理：**

1. 顶部 4 张卡片实时显示物理内存使用率（带进度条）、可用内存、页面文件占用和系统缓存；
2. 清理区域共 6 项，勾选后点 **开始清理**，也可以对单项点「清理该项」（**v3.7.1 起清理动作改由 Rust 原生引擎执行**，无 pwsh 冷启动延迟）：
   - 工作集、低优先级备用列表、合并物理内存页：默认勾选，安全；
   - **修改列表、备用列表（全部）属于高风险**，执行前会弹红色二次确认，执行时系统可能短暂卡顿一下；
   - **顽固软件专杀**（默认不勾）：一次性结束 MuMu 模拟器、网易 UU 远程、抖音、剪映、WPS、微软电脑管家的后台常驻和守护进程（包括前台窗口，请先保存手头工作），结果以右上角提示和日志形式反馈；
   - 点区域条目可看详细简介（本地简介 + 可选的联网 AI 简介）；
3. 清理完成后会显示释放了多少内存，并自动刷新数据。

> 原理与权限：内存清理调用 Windows 系统接口（和 Mem Reduct 同款原理），**必须管理员权限**，没有权限会提示提权。释放多少取决于当前系统状态，一般是已用内存的 10%–50%。

**应用进程管理：**

内存清理页的「运行中的进程」是一张一行式入口卡片，点右侧 **去管理** 打开独立窗口，可与主窗口并排操作：

- 同一路径的进程自动合并成一组（类似任务管理器的进程树），默认折叠，点行展开/收起，可对单个子进程单独结束；
- 应用图标直接从可执行文件提取，提取失败时显示内置兜底图标；
- 支持按名称或 PID 搜索、手动刷新，结束进程前二次确认；
- 在子窗口结束进程后，最新统计会实时回传到主页面卡片上。

## 四、电脑优化中心与系统还原点

1. 进入「优化电脑」页，126 个优化项按 12 个分组显示成卡片（按本机磁盘类型过滤，SSD 通常可见 123 项）；
2. 点卡片可看详情：执行步骤、风险等级、**预期效果**（明显/一般/微小/未验证的经验分级，非本机实测）、优缺点；
3. 点 **立即执行** 前会自动检查还原点：从没建过会弹窗建议先建，5 天内建过则静默放行；
4. 可勾选多张卡片后点 **执行所选优化**，或点 **全选执行** 跑当前页全部项目；
5. **高危操作**（禁用 UAC、关闭 Defender、批量禁用 70 多个服务等）执行前会弹红色警示二次确认；其中「禁用 70+ 非必要服务」还会**单独弹窗询问是否连商店相关服务一并禁用**（点「禁用」会影响应用商店的使用、更新与下载及系统更新；点「不禁用」则商店服务保持默认）；
6. 执行时有实时进度条，完成后弹提示；**执行成功后程序会立即回读注册表核对**，读回值与预期不符（例如被组策略或安全软件改回）会明确提示「已执行但读回校验不符」，不会静默假成功；
7. **已应用清单（v2.6 新增）**：每次执行前都会把「改了什么」记入本机状态文件（含服务启停等注册表备份覆盖不到的步骤）；**进入优化中心页时自动全量扫描一遍可检测项并持久保存**（安装版在 `%APPDATA%\com.xiaoxu.trim`，便携版在程序目录 `data` 文件夹），执行/还原后即时更新记录；启动时发现「执行中断、被系统回写导致状态不明」的项，优化中心顶部会出现提示条，可**一键还原**；
8. 优化项日后从目录退役时，其执行前记录仍保留在备份文件里；**本版本不会在启动时自动还原退役项**（无人确认的注册表写回与本应用的安全模型冲突），但退役项的备份有还原出口：仍留有注册表备份的会在「优化电脑」页顶部列成待还原提示条，可逐项按原值还原（需管理员权限）；
9. **还原也会回读核对**（v3.7.0）：点还原之后同样会重新读取注册表，只有读回值与「未生效」一致才算还原成功；读不回来会如实标成「部分还原」并保留备份供重试，不会把「跑了一遍命令」当成「已经恢复」。

**Windows 更新三态（v3.7.0）**：想推迟更新请用 **Windows 更新：暂停到日期**（1~35 天档位，走官方暂停键，服务照常运行、到期自动恢复），这是推荐路径；想恢复用 **Windows 更新：恢复自动更新**（只清 Trim 自己写过的键）；**Windows 更新：彻底禁用** 属高危项，需红色二次确认，安全补丁将不再自动送达。

> **重要**：126 项里有 14 项高风险，其中 **9 项执行后无自动还原**（其余 5 项支持一键还原）。凡是动服务、驱动、注册表、启动参数的，务必**先建系统还原点**——可直接勾选「创建系统还原点」项一键创建。

**系统还原点：** 在优化中心右上角点 **系统还原点** 打开弹窗，能看到各磁盘的保护状态、还原点数量和最近一次还原点时间；点 **创建还原点** 会为所有已开启保护的磁盘建还原点。优化后万一异常，去系统设置里还原即可。

## 五、启动项管理

1. 进页面自动扫描（注册表 Run/RunOnce、启动文件夹、登录与开机计划任务）；**首次读取的是上一次的扫描缓存**，页面顶部会标明「数据来自 N 分钟/天前的扫描」，同时后台自动重扫，重扫完成后列表与徽章一并刷新，有需要也可以点 **立即重新扫描**；
2. 勾选项后可 **启用/禁用**（随时可逆）或 **删除**（删除前自动备份，不可逆）。禁启用与系统「任务管理器」**同轨**：禁用时保留注册表里的 Run 值、只写系统的 `StartupApproved` 标记，所以随时能原样还原，也不会把条目变成「注册表里查无此项」的幽灵；徽章会区分 **启用 / 已由 Trim 禁用 / 已由系统禁用 / 已从系统消失** 四种状态；
3. 可 **打开所在位置** 找到源文件，也可手动 **添加** 启动项，重名会提示冲突，不会静默覆盖；
4. 点条目（非按钮区域）可看详细简介，支持联网 AI 简介。

## 六、右键管理

1. 进页面按 16 类自动扫描：文件、EXE、LNK、目录、文件夹、驱动器、回收站、目录背景、桌面背景、此电脑、库、发送到、新建菜单、打开方式、Win+X、UWP 应用；
2. **勾选 = 启用，取消勾选 = 禁用**，随时可以改回来。禁用会同时写 `LegacyDisable`、`ProgrammaticAccessOnly`、`HideBasedOnVelocityId` 三个值（Windows 自己的隐藏约定），启用时一并清除；`Folder\shell\opennewwindow` 例外，它不写 `LegacyDisable`，否则会连带废掉 Win+E；
3. 「打开 / 浏览」这类基础动词在取消勾选时会先弹**红色二次确认**——禁掉它们最直观的后果是双击打不开；
4. 行内 **备份并删除** 是不可逆操作，删除前会自动备份注册表项和文件类条目（「发送到」、Win+X 的 .lnk 走回收站）；备份按项所在的**真实注册表分支**导出（HKCU 的项恢复回 HKCU，不会变成全机项），文件类删除失败或备份失败都会中止删除；
5. 改完不会立刻在右键菜单里看到变化——右键菜单是资源管理器加载时解析的。页面顶部会出现「N 项改动待生效」提示条，攒够了点一次 **重启资源管理器** 即可（只重启当前登录会话的 explorer，会关掉已打开的文件夹窗口，所以有红色确认）；
6. 页头 **菜单形态** 按钮展开两张卡：
   - **Windows 11 右键菜单形态**：在「经典完整菜单」（扩展全部平铺，等同 Win10）与「新版精简菜单」（扩展折叠进「显示更多选项」）之间切换，只改当前用户，切换后需重启资源管理器；
   - **已屏蔽的 Shell 扩展**：列出 `Shell Extensions\Blocked` 里的 GUID（分 HKCU / HKLM 两级）。这张表比改键名更彻底，也常被别的工具改动；命中屏蔽表的项在列表里显示为「已屏蔽」。UWP / 打包应用的扩展就是靠这张表实现可逆启停的。系统内置扩展**不允许**加入屏蔽表，否则整个新式菜单可能失效；
7. 列表里的徽章会说明状态来历：**已禁用**（Trim 的可逆禁用）、**已禁用·外部约定**（别的工具如 Autoruns 改名禁用，Trim 没动它）、**已屏蔽**（屏蔽表）、**残留**（登记的组件文件已不存在，或新建菜单里挂着已卸载的类型，可安全清理）；
8. 点条目看详情：注册表路径、**实际所在分支**（真实 hive）、组件路径、CLSID、风险提示 / 失效残留 / 屏蔽来源等状态说明，也可调用联网 AI 简介；
9. 左侧有聚合视图（全部 / 磁盘分区 / 所有对象 / 新建菜单 / 打开方式 / Win+X 等），方便按场景找。

## 六点五、默认应用设置（改由系统完成）

> **v3.7.0 起，本产品不再提供「默认应用接管」功能。** 原页面、相关脚本、IPC 通道与「专家模式」开关已全部移除。

改默认打开方式请直接用 Windows 自带的设置页：**设置 → 应用 → 默认应用**。这是唯一不需要绕过系统防篡改保护的途径，也不会被 Windows 更新回滚。

**为什么不再做**：曾经的两条路径里，策略路径依赖 HKLM 策略键、只在下次登录生效；专家模式路径需要临时禁用 `UCPD` 保护驱动（内核态防篡改保护层），既容易被安全软件判为风险行为，也会被 Windows 更新重新启用——收益与风险不成比例。Trim 继续坚持「不静默禁用内核驱动、不绕过安全层」这条线。

> 说明：卸载旧版本后，`%APPDATA%\com.xiaoxu.trim\defaultapps-scan.json` 这个历史扫描缓存不会被自动清理，可手动删除，不影响任何功能。

## 七、磁盘测速 / 网络测速 / 网络检测 / 实时网速

- **磁盘测速**：设置好测试路径（默认自动选当前用户的「下载」目录）、块大小、队列深度、线程数和时长后开始；测试会在目标目录建临时文件，结束自动删除，可保存历史记录做对比。**v3.7.1 起由 Rust 原生引擎执行**（OVERLAPPED 异步 I/O，默认绕过文件系统缓存直测设备吞吐），QD 表示每个线程的在途请求上限、线程数真实生效；历史记录带引擎标识（原生/PS），两种引擎口径不同不可直接横向对比。
- **网络测速**：点开始后选 **SpeedTest.cn** 或 **中国科大** 节点，需要联网，数据由对应站点提供。
- **网络检测**（v3.0 新增）：点 **开始检测** 后逐项给出结论，共 6 项只读检查——网络硬件配置、网络连接配置、DHCP 服务、DNS 服务、Web 代理设置、连通性；每项都带证据数据（网卡速率、网关延迟、DNS 列表等），检测本身不改系统。异常项会给出原因与建议，**一键修复** 按固定白名单动作执行（启用被禁用的网卡、启动 DHCP/DNS 服务、重置 DNS、关闭残留代理、重置 WinHTTP 代理），需管理员权限的动作会弹 UAC；连通性/DNS 项还联动「系统维护」的深度修复（刷新 DNS 缓存、重置网络栈）。
- **实时网速**：进页面开始采集，显示上下行曲线和丢包率，可暂停、切换网卡，离开页面自动停。点右上角 **记录数据** 开始录制，再点 **停止录制** 自动生成带每秒折线的报告，存在 `%APPDATA%\com.xiaoxu.trim\cache\realtime-reports\`，报告保留 **7 天自动清理**。**v3.7.1 起采样改由 Rust 原生引擎执行**（单进程常驻采样，替代每秒拉起 pwsh 的旧实现，CPU/内存占用更低）。
- **系统概览**：**v3.7.1 起高频指标（CPU / 内存 / 磁盘 / 进程数）改由 Rust 原生引擎采集**，无 pwsh 冷启动延迟；CPU 占用率由主进程对原始计数做差分得出。

## 九、联网 AI 简介怎么用

启动项、右键管理、内存清理的详情里提供「简介」，分两层：

- **本地简介**：内置在程序里，打开就有，**不联网、不上传任何信息**；
- **联网 AI 简介**：只有你主动点 **获取 AI 简介** 才会请求网络，且只上传「项目名称 + 厂商/分组」，不含注册表路径、文件路径或账号信息；
- 各模块的 AI 简介各自独立：统一全局模型选择，各模块分别缓存（7 天有效）；
- 所选模型没启用时，点「获取 AI 简介」会直接打开大模型管理窗口引导启用。

**配置模型：** 在 **设置 → 大模型管理 → 去管理** 里配置，共四项：百度千帆、知乎直答、秘塔 AI、自定义模型（兼容 OpenAI chat/completions 协议）。**所有内置模型默认关闭、密钥留空**；填入密钥点保存后会自动发一条测试消息，校验通过才启用，密钥只保存在本机 `%APPDATA%\com.xiaoxu.trim\settings.json`，不会上传。

## 十、安全须知

1. 清理、右键菜单修改、启动项删除，建议保持二次确认开启；
2. **执行高风险优化项前一定先建系统还原点**——14 项高风险里 9 项无自动还原；
3. 删除类操作（右键项、启动项、文件清理）执行前会自动备份，但备份代替不了还原点，动系统级设置前还是建议先建还原点；
4. 磁盘清理的两个高风险项（Windows Installer 补丁缓存、DISM 组件清理）会影响系统更新的卸载能力，默认策略下不执行（执行结果中标注「按默认策略跳过」）；
5. 会访问外网的功能：网络测速、联网 AI 简介、运行库修复（微软官方直链下载安装包）、OOSU 隐私工具（O&O 官方直链下载 exe 并做 SHA-256 校验，配置内置在程序里）、自动更新（启动后静默检查）、清理规则库在线更新；其余功能全部在本机完成；
6. 本工具仅供个人测试交流，使用风险自负；
7. 部分背景来源于网络，如有侵权，联系删除。

## 十一、不做的事（已知无效或有代价的常见「优化」）

Trim 的原则：**说不清收益的改动，宁可不做**。以下常见「优化技巧」经实测或公开机制分析后，Trim 刻意不提供或已收敛为只读提示——列出来说明原因，帮你省下试错的功夫：

- **清空整个待机列表「释放内存」**：待机列表本来就计入可用内存，强行清空丢掉的是热缓存（公开实测中曾出现清掉近 19 GB 系统缓存只换来几百 MB「可用内存」的情况）。Trim 的内存清理只提供工作集、低优先级备用列表等收益明确的区域；
- **修改启动配置数据（BCD）类「玄学参数」**：无论计时器合并、动态时钟，还是关开机动画、关启动调试、改超时等待，机制上都属启动配置改动而非性能优化，收益不可测且失误会影响开机。Trim **完全不读写 BCD**，这类改动一律不提供；
- **MMCSS 给游戏提优先级**：实测无可测收益，不提供；**音频任务调度**的两项不在本条范围内，仍作为优化项提供——它们改的是 MMCSS 音频类任务的分派参数，和「给游戏抢优先级」不是同一件事，别把两条承诺混着理解；
- **禁用全屏优化（FSO）/ 关 MPO**：会连带丢失 Auto HDR 与可变刷新率，或让画面全部改走合成影响录制捕获，代价大于收益。**边界说明**：「关闭游戏 DVR 录制」一项仍会顺带写入全屏优化的兼容开关，那是录制关掉后的附带条件，不构成向用户提供 FSO 开关；
- **高频率自动「内存整理」**：反复清空工作集只会把数据换回页面文件再读回来，徒增磁盘 IO；
- **禁用系统服务「越全越好」**：盲目禁用会破坏更新、同步、打印等基础能力；Trim 的批量禁用清单里，商店与同步相关服务保持系统默认不再修改；
- **MSI 中断模式 / 中断亲和性调优**：无法可靠验证设备是否支持消息信号中断，误开会导致设备失联，不提供；
- **AMD 驱动注册表深度调优**：A 卡用户实机反馈存在副作用，只保留清理类规则。
- **静默/永久禁用 UCPD 驱动来接管默认应用**：该驱动是系统对默认应用选择的防篡改保护层，静默禁用内核驱动 + 计划任务易被安全软件判为风险行为，且 Windows 更新会重新启用。v3.7.0 起「默认应用接管」功能已整体移除，Trim 不再提供任何禁用该驱动的入口；批量服务优化项同样不会连带禁用它。

> 如果你见过其它「必开优化」没出现在 Trim 里，大概率属于上述某类——先查机制、再做实测、最后才动手，是这把工具的取舍标准。

## 十二、日志与反馈

- 所有操作记录在 `%APPDATA%\com.xiaoxu.trim\logs\`，可在「操作日志」页查看和导出；
- **v0.2.7 起，界面侧的异常也会进同一份日志**：JS 报错、未处理的 Promise 拒绝、图标/脚本加载失败都会带「是哪个窗口报的」记一条 ERROR（每次打开页面最多 20 条，避免一处循环报错刷屏）。所以遇到白屏、按钮没反应、图标不显示这类问题，直接导出日志就带着线索，不必复现；
- 配置和缓存都在 `%APPDATA%\com.xiaoxu.trim\` 下（settings.json、paths.json、cleanup、cache 等）；
- **误报反馈模板**（清理或卸载残留把不该动的东西列进来了）：提 issues 时请带上这几项，缺一条就要来回追问一轮——
  ① 应用版本（「关于」页或安装目录 `Trim.exe` 属性）；
  ② 规则库版本（操作日志里搜「清理规则库已装载」，那一条带 `rulesVersion` 与来源）；
  ③ 条目 `id` 与该条的规则版本（残留候选的悬停依据里写明了「来自…规则 xxx（规则版本 yyy）」；清理项的 id 在明细里）；
  ④ 被点名的具体目标（完整路径或注册表键），以及为什么认为它不该动；
  ⑤ 导出的日志（不必复现，日志里带着判定来源）；
- **漏报反馈模板**（该被识别为残留/可清理的东西没列出来）：带 ①② 与 ④——目标实际位置、它属于哪个程序的哪一类数据（配置 / 缓存 / 日志 / 卸载键），以及本机是否存在该程序的卸载记录。规则库是签名发布物，**不会按用户提交的文本直接入库**：每条都要人工复核来源后重写，并在 `prov` 里登记出处与评审日期；
- 说明：每条清理/残留规则都带**条目级版本戳**（与整库 `rulesVersion` 同值，由 `tools/stamp-rule-ver.mjs` 在抬版本时统一重刷），「上次报了这次没报」这类问题能指认到具体是哪一版规则判的；
- 问题或建议欢迎提交issues。

## 十三、覆盖承诺（覆盖什么 / 明确不覆盖什么）

规则库的覆盖面不是"越多越好"的口号，而是一份可核对的口径（由 `tools/gen-rule-coverage.mjs` 每次改库后重新生成，基线只增不减，缩水会在验收门禁里判红）：

- **「有效」的定义**：一条规则至少有一个当前引擎真会读的路径来源（`pathPs` / `fileKeys` / `regKeys` / `detect`），或带已登记的专用分流标记（`special=dism`、`fileCleanType`）。定义与装载侧校验同源——引擎读不到的键写了也等于没写；
- **当前覆盖**：清理库 76 条全部有效（system 35 / app 23 / browser 9 / gfx 5 / special 4），残留库 6 条按条件组匹配全部计入；
- **明确不覆盖**（写下来才有边界，空着等于没想过）：
  1. **残留候选里的 Windows 服务与设备实例**：判据成立，但删除要提权走 SCM 与 SetupAPI，缺实操经验；误删一个服务或设备实例的代价远高于多列两类候选的收益（v0.2.7 按风险裁定撤除）；
  2. **AMD 驱动注册表深度调优**：A 卡用户实机反馈存在副作用，只保留清理类规则；
  3. **winapp2.ini 整库导入**：可直译率仅 16.3% 且许可要求派生署名，批量导入会制造不可溯源的规则；
  4. **SpaceMint 云端规则库抓取导入**：语法可直译率≈100%，但协议明文禁止批量抓取服务数据且下载需登录，只借字段模型；
  5. **永久删除兜底**：除「常规清理项」外一律回收站优先，回收站失败不做永久删除兜底（刻意收紧，上游同类工具会兜底）；
  6. **优化项目录与清理规则的在线热更**：两条规则库（清理 / 卸载残留）都随版本整体交付、附 ed25519 签名并由门禁对拍，**没有「检查更新并热替换规则」这种入口**。残留规则库确实有「在线更新」动作，但它是一次**显式、由用户点击触发**的下载替换（写入前整包语义校验、失败整包拒绝并隔离），不是后台定时替换。要加优化项或规则，方式是等新版本。
